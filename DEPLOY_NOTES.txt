DEPLOY NOTES — Clone to a New Laptop & Push to Another Workspace
=================================================================

PREREQUISITES
-------------
- Python 3.10+
- uv:               pip install uv
- Databricks CLI:   https://docs.databricks.com/dev-tools/cli/install.html
- Node.js (if frontend assets need rebuilding)


STEP 1 — Clone the repo
-----------------------
  git clone https://github.com/prasadvenkat22/dbx_app.git
  cd dbx_app


STEP 2 — Install Python dependencies
-------------------------------------
  uv sync


STEP 3 — Authenticate to the new workspace
-------------------------------------------
  databricks configure --profile new-workspace

  Enter your workspace URL and a personal access token when prompted.
  Token: Databricks UI → Settings → Developer → Access tokens


STEP 4 — Update databricks.yml
-------------------------------
  Edit the dev (or add a new) target to point at the new workspace:

    targets:
      dev:
        workspace:
          host: https://YOUR-NEW-WORKSPACE.azuredatabricks.net
          profile: new-workspace
        variables:
          catalog: workspace
          schema: ${workspace.current_user.short_name}
          warehouse_id: "YOUR_WAREHOUSE_ID"
          lakebase_host: ""       # leave blank if not using Lakebase
          lakebase_endpoint: ""

  WHERE TO FIND VALUES
  - warehouse_id     : Databricks UI → Compute → SQL Warehouses
                       → your warehouse → Connection details tab
  - lakebase_host /
    lakebase_endpoint: Databricks UI → Compute → Database instances
                       → your instance → Connection details tab
                       (leave blank if not using the bookings feature)


STEP 5 — Deploy and run
------------------------
  databricks bundle deploy -t dev
  databricks bundle run -t dev wanderbricks_app


TIPS
----
- To keep the old workspace and add a new one, add a second target (e.g.,
  "staging") in databricks.yml and deploy with: -t staging
- The bundle UUID in databricks.yml is fine to reuse across workspaces —
  each workspace tracks its own deployment state independently.
- After deploy, the app URL is printed in the CLI output or visible in
  Databricks UI → Compute → Apps.
