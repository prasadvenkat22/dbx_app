
  1. Authenticate the Databricks CLI against the new workspace

  databricks configure --profile new-workspace
  Enter the new workspace URL and a personal access token (or use OAuth). This saves credentials to
  ~/.databrickscfg.

  2. Add a new target in databricks.yml

  Add a block under targets: (e.g., staging) pointing at the new workspace:

    staging:
      mode: development
      workspace:
        host: https://your-new-workspace.cloud.databricks.com
        profile: new-workspace          # matches the profile from step 1
      variables:
        catalog: workspace              # must exist in the new workspace
        schema: ${workspace.current_user.short_name}
        warehouse_id: "YOUR_WAREHOUSE_ID"   # from Compute → SQL Warehouses
        lakebase_host: ""
        lakebase_endpoint: ""

  3. Get the warehouse ID in the new workspace: Compute → SQL Warehouses → your warehouse → Connection details
  → copy the ID.

  4. Make sure samples.wanderbricks exists — the app queries that Unity Catalog schema. If it's not available
  in the new workspace, the data layer in wanderbricks.py will need a different catalog/schema.

  5. Deploy and run

  databricks bundle deploy -t staging
  databricks bundle run -t staging wanderbricks_app

  The bundle will build the Python wheel, upload it, create the Databricks App resource, and start it.

  ---
  Key things that must exist in the new workspace before deploying:
  - A running SQL Warehouse (for the statement execution API)
  - The workspace catalog (or change the catalog variable to one that does exist)
  - The samples.wanderbricks schema, or update the queries in wanderbricks.py to point at your data

  Your dev target is already configured. Just run:
  
  databricks bundle deploy -t dev

  Then to start the app:


  databricks bundle run -t dev wanderbricks_app

  That's it — no config changes needed since the workspace, warehouse ID, and credentials are already set in
  databricks.yml.
